
# 1. 原子操作

原子操作指的是: 在多线程环境中, 原子操作是不可被线程中断、要么完整执行成功、要么完全不执行，不存在中间状态的操作

![[409abc18-6d5e-4829-b331-42384077f61e.png]]

现代计算机的架构是这样的, 一个处理器里面可能有两个CPU核心, 四个处理器就是八核, 一个CPU中, L1和L2缓存是每一个CPU独有的, L3缓存是处理器共享的(L123也叫一级/二级/三级缓存), 下面的主存指的就是内存

综上所述, 当全局变量A被所有线程修改时, 假如说就在CPU0里面修改, 那么对于CPU1来说, 这个全部变量A要么是修改后的值, 要么就是修改前的值, 不能存在中间态, 这就是原子性

```cpp
// 对于一行代码而言
int A = 10;
A++;

//A++只是一行代码, 但是解释为汇编语言时, 可能是三条指令
//原子操作就是需要把这三条指令在CPU中全部执行完才退出
```

如何实现原子性? 有几种不同的情况:

1. 单处理器单核: 同时只能运行一个线程, 只需要保证这个操作指令不要被打断就行了
- 底层自旋锁
- 屏蔽中断: 像网卡来数据时, 需要CPU参入去拷贝数据, 就会有硬件中断, 告诉CPU先处理我这件事

1. 多处理器或多核: 除了要屏蔽中断以外, 还需要避免其他核心操作相关内存空间

# 2. CPU的读写策略

现在再来探讨一下CPU读写内存数据的策略:

**读策略**:
1. 情况一: 操作的变量在缓存中, 直接命中缓存后写, 并标记为脏数据
2. 情况二: 缓存没命中, 使用LRU策略, 找到最近使用最少的缓存块, 若该缓存块有脏数据, 把数据刷回主存, 然后把内存中的数据写到缓存, 若不是脏数据, 就从内存把这个数据读到缓存, 并标记为脏

> 写策略指明, 写数据并不是立马把数据刷到主存中, 而是先会在缓存中呆着, 等LRU策略被刷回内存

**读策略**:
1. 情况一: 要读的变量在缓存中, 命中缓存直接返回
2. 情况二: 没有命中缓存, 根据LRU策略, 找到最近使用最少的缓存块, 若是脏数据, 则刷到主存, 然后从主存把目标数据拿到缓存, 标记为非脏, 若不是脏数据, 从内存读到这个缓存后, 标记为非脏

> 读策略指明, 读数据会立马把数据拿到缓存中


![[03c17bb0-f407-4b71-9b02-5ffe1651b499.png]]

缓存的基本单位就是cache line, 64字节
![[dda7b21e-ec2b-4a1f-b867-d80f4905ecde.png]]


CPU的这种机制, 会出现缓存不一致的问题, 加入核心0将变量A的值从2修改为3, 修改后, 并不是立马刷到主存的, 这时核心1去读变量A的值, 就会读到内存中的2, 而不是修改后的3

# 3. 缓存不一致的解决方案

基本的思路是, 当一个CPU核心写某个数据的时候, 能不能传播给其他的核心, 让他们不要轻易的去读

1. 总线嗅探机制(bus snooping): 监听和发布机制, 当核心1修改变量A时, 会广播给核心2 3 4
2. 事务的串行化: 一旦核心1写完变量A后, 向核心2 3 4广播, 若不是串行化的, 会有这种情况发送, 离核心1近的核心, 会先收到通知, 离核心1远的核心, 会后收到通知, 这样会造成顺序错乱, 因为核心2 3 4有可能同时在修改变量A
![[0e5cdd81-8d2b-4226-a023-6d662b92c622.png]]

==MESI一致性协议: 他会对每一个cache line制定一个状态==
![[Pasted image 20260804210944.png]]

- modify: 已修改, 和上面说的, 标记为脏是一个意思, 某个数据块已修改, 但没有同步到内存
- exclusive: 独占, 这个数据只被一个核心读过, 并没有写, 其他核心不关心
- shared: 共享, 某个数据被多个核心加载过, 但是并没有写
- involidated: 失效, 假如核心1之前读过数据A, 数据A在核心1的缓存块中, 此时核心2把数据A修改了, 这个修改又没有刷到内存, 那么核心1中的数据A缓存块会被标记为失效

所以说, 原子性的实现, 本质上就是:
硬件自旋锁 + 屏蔽中断 + 锁总线 锁住MESI一致性协议中的ME状态

原子操作和互斥锁其实并没有什么关系, 原子操作的lock和我们互斥锁的mutex_lock是不一样的

# 4. 了解内存序

CPU和编译器会对代码进行优化, 为了提高运行速度, 会对指令进行重排

```cpp
int i = 1;
int j = 1;
i += 1;
j += 1;
// 重排后
int i = 1;
i += 1;
int j = 1;
j += 1;

// 两个相关的指令会放到一起
```

内存序有两个作用:
1. 顺序性问题, 指导CPU和编译器的优化
2. 可见性问题(同步), 某个线程对内存地址更新, 何时能被其他线程看见
