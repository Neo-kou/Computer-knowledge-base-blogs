#  2. shell命令以及运行原理
Linux操作系统严格来说是:
Linux内核+Linux外壳+配套程序

![在这里插入图片描述](https://i-blog.csdnimg.cn/blog_migrate/c1e6d3b6bf0deb3413fdadc79851286b.png)
==外壳也就是shell==
**那么为什么要存在外壳呢?
有两个原因:**

1. **`命令行解释`(充当媒婆)**

>**内核的设计非常复杂,使用者无法
直接向Linux内核进行沟通,也无法
直接读懂内核执行完命令的结果
所以shell外壳充当"媒婆"这一角色
来往于操作者和内核之间**

- <font color = blue>外壳程序将用户输入的指令解释后
传递给内核</font>
- <font color = blue>内核执行命令后得到的结果经外壳
处理后传递给用户</font>


2. **`保护内核`(充当保安)**

>**有时用户想要内核执行的命令过于离谱
>或者使用的指令内核根本做不到
>那么此指令根本不会"打扰"内核
>它会在shell外壳进行翻译时就被驳回!**

- <font color = blue> 就像你暗恋的女生有男朋友了
你还要媒婆帮你说媒</font>

- <font color = blue> 这个请求会在媒婆这一阶段就驳回! </font>

![在这里插入图片描述](https://i-blog.csdnimg.cn/blog_migrate/e44cd376bf0527dafacec29762d55271.png)

`注:shell是对所有命令行解释器的统称`

Linux下的shell外壳是bash
而windows下的shell外壳是
图形化界面

#  7. 对文件夹的权限理解
和普通文件不同,文件夹的读写
和可执行权限对应的功能十分不同

- <font color = red>读权限( r ):用户能否查看文件夹下文件的信息</font>
- <font color = red>写权限( w ):用户能否在此文件夹下创建/删除文件</font>
- <font color = red>可执行权限( x ): 用户能否进入此文件夹</font>

==比如在我的目录下有一个source文件夹:==

![在这里插入图片描述](https://i-blog.csdnimg.cn/blog_migrate/20af9e53ab7fe9d8f15cdec1b48d9610.png)

**拥有者可以进入文件夹,并且可以创建/删除文件
也可以使用ls相关指令查看文件的信息
但是所属组和other不能创建或删除文件**

==现在切换为用户kwy并且进入此文件夹:==

![在这里插入图片描述](https://i-blog.csdnimg.cn/blog_migrate/e24ab8fd06b4a55abbfe8983b3b2ded2.png)

**`当我创建文件时,权限就被限制了!`**

#  8. 默认权限以及权限掩码
我们先创建一个目录和一个普通文件:

![在这里插入图片描述](https://i-blog.csdnimg.cn/blog_migrate/467ea65eba46d38f4a19e5f31bd8c9e3.png)


我们会发现以下规律:

- **目录的默认权限为:`7 7 5`**
- **普通文件默认权限: `6 6 4`**

==这是为什么呢?==

其实文件的默认权限有两个因素决定:

1. <font color = blue>文件的起始权限</font>
2. <font color = blue>文件的权限掩码</font>

==文件的起始权限:==

- **目录的起始权限为:`7 7 7`**
- **普通文件的起始权限为: `6 6 6`**

==文件的权限掩码:==
查看文件的权限掩码:

>**使用指令: `umask`**

**我的机器上默认为002
用起始权限777-002=775
刚好就等于目录的默认权限
而起始权限666-002=664
刚好也等于普通文件的默认权限**

***
##  8.1 权限掩码相关的计算
其实文件的默认权限并不是简单的等于:

**起始权限 - 权限掩码**

==它的公式是:==

**`最终权限=起始权限&(~权限掩码)`**

公式不好记,但是说起来简单易懂

1. <font color = gree>将权限掩码和起始权限变成二进制</font>
2. <font color = gree>将这两个二进制对一一对应</font>
3. <font color = gree>权限掩码为1,起始权限为1时,起始权限改为0</font>
4. <font color = gree>权限掩码为0,起始权限也为0时,起始权限不变</font>

#  9. 总结以及拓展
Linux中的权限十分分明,一个用户
能干什么不能干什么都已经规定好了
不会出现你的某位同事删掉你的代码这种事情

==拓展: 粘滞位==

假设你和你的同事在同一个目录下工作
你要创建文件就必须有目录的w权限
而拥有w权限也不一定完全安全.
可能你的小组某个"间谍"
会删除你们小组所有文件

![在这里插入图片描述](https://i-blog.csdnimg.cn/blog_migrate/fa0fa65021d9f060276df25d7d459f96.png)


**`然而想要正常工作又必须将w权限放开`**

为了解决可以创建文件而不能删除他人文件
这个问题,引申出了粘滞位

详情请看:[粘滞位讲解](https://www.cnblogs.com/MrListening/p/5813281.html)
